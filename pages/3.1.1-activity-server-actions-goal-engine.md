## Server Actions & Validation Engine (`src/lib/actions/activity.ts`)

The server actions module manages mutations for user activity goals and manual activity logs. All actions execute inside Next.js Server Actions (`"use server"`), gating execution via session checks (`requireUserId`) and interacting with Supabase. Cache invalidation across components is driven by calling `refresh()`.

### Goal Mutation: `saveGoal`
The `saveGoal` function handles creating new goals or updating existing ones when an `id` field is present in the `FormData` payload `src/lib/actions/activity.ts:27-68`.
- **Validation**:
  - Validates UUID format if an `id` is supplied `src/lib/actions/activity.ts:33`.
  - Validates `direction` (`isGoalDirection`), `unit` (`isGoalUnit`), and `period` (`isGoalPeriod`) `src/lib/actions/activity.ts:34`.
  - Ensures the unit/period combination is permitted via `allowsPeriod` `src/lib/actions/activity.ts:35`.
  - Checks target numeric constraints, range limits (`maxTarget`), and integer requirements for whole-number units (`goalUnit(unit).decimals === 0`) `src/lib/actions/activity.ts:37-41`.
- **Storage & Limits**:
  - Converts display targets to storage units using `toStoredTarget` `src/lib/actions/activity.ts:46`.
  - Enforces `MAX_ACTIVE_GOALS` (10 active goals per user) on insertions by querying `activity_goals` with exact count heads `src/lib/actions/activity.ts:57-62`.
- **Cache Refresh**: Invokes `refresh()` upon successful database upsert/insert `src/lib/actions/activity.ts:66`.

### Goal Retirement: `removeGoal`
Retires an active goal by performing a soft delete (`active: false`) on the `activity_goals` table `src/lib/actions/activity.ts:71-78`. Historical activity logs remain untouched `src/lib/actions/activity.ts:70`.

### Effort Rating: `setEffort`
Rates the perceived exertion of an activity log (manual or device-synced workout) `src/lib/actions/activity.ts:88-97`. It parses the effort input via `parseEffort` `src/lib/actions/activity.ts:81-85` and updates the `effort` column in `activity_logs` `src/lib/actions/activity.ts:95`.

### Manual Activity Deletion: `removeActivity`
Deletes hand-logged activities where `source` equals `'manual'` `src/lib/actions/activity.ts:103-110`. Device workouts are purposefully excluded to prevent re-sync conflicts `src/lib/actions/activity.ts:99-102`.

### Manual Logging: `logActivity`
Allows users to log custom activities (e.g., stretching, sauna sessions) `src/lib/actions/activity.ts:115-147`.
- **Validation**:
  - Truncates and checks activity name (max 60 characters) `src/lib/actions/activity.ts:116`, `src/lib/actions/activity.ts:122`.
  - Validates duration (1 to 1440 minutes) `src/lib/actions/activity.ts:123` and distance bounds (0.1 to 200 miles, converted via `METERS_PER_MILE`) `src/lib/actions/activity.ts:7`, `src/lib/actions/activity.ts:124`, `src/lib/actions/activity.ts:138`.
  - Restricts days to `'today'` or `'yesterday'` `src/lib/actions/activity.ts:125`.
- **Side Effects**: Inserts row into `activity_logs`, records a daily check-in via `recordCheckin`, and triggers `refresh()` `src/lib/actions/activity.ts:133-146`.

Sources: `src/lib/actions/activity.ts:1-147`, `src/lib/catalog/daily-stats.ts:1-1`

## Goal Catalog Definitions (`src/lib/catalog/goals.ts`)

The goal catalog defines metrics, units, periods, and conversion utilities.

| Unit Constant | Storage Unit | Device Metric | Allowed Periods | Decimals | Max/Day |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `steps` | `steps` | Yes (`true`) | day, week, month | 0 | 100,000 |
| `distance_m` | meters | No (`false`) | day, week, month | 1 | 100 |
| `minutes` | minutes | No (`false`) | day, week, month | 0 | 1,440 |
| `active_days` | days count | No (`false`) | week, month | 0 | 1 |
| `active_kcal` | calories | Yes (`true`) | day, week, month | 0 | 10,000 |

### Key Utility Functions
- `isGoalUnit`, `isGoalPeriod`, `isGoalDirection`: Type guards validating raw inputs `src/lib/catalog/goals.ts:93-103`.
- `toStoredTarget` / `toDisplayTarget`: Handles unit scaling (e.g., converting miles to meters using `METERS_PER_MILE`) `src/lib/catalog/goals.ts:127-135`.
- `describeGoal`: Generates human-readable natural language strings for goals (e.g., *"At least 10,000 steps a day"*) `src/lib/catalog/goals.ts:148-160`.

## Goal Progress Engine (`src/lib/goals.ts`)

The goal engine evaluates progress dynamically upon page rendering without persisting computed results `src/lib/goals.ts:4-8`. 

### Data Structures
- `Goal`: Defines unit, period, direction, target, activity filter, and `createdOn` timestamp `src/lib/goals.ts:10-19`.
- `ActivityRow`: Represents minimal activity data required for aggregation (`activity`, `duration_min`, `distance_m`, `logged_on`) `src/lib/goals.ts:21-26`.
- `GoalProgress`: Output structure holding current period values, historical period arrays, time elapsed calculations, and achievement status (`met`, `to_go`, `under`, `over`) `src/lib/goals.ts:57-70`.

### Evaluation Algorithm: `goalProgress`
The `goalProgress` function computes totals across historical period intervals (`historyStarts` for day, week, or month) `src/lib/goals.ts:45-53`, `src/lib/goals.ts:76-126`.
- For **device-backed metrics** (`steps`, `active_kcal`), values are summed from the `deviceDaily` map `src/lib/goals.ts:86-97`.
- For **manual/activity-backed metrics** (`minutes`, `distance_m`, `active_days`), values filter through matching activity rows and aggregate via summation or `Set` cardinality `src/lib/goals.ts:98-101`.
- Past periods prior to `goal.createdOn` are filtered out from judgment counts `src/lib/goals.ts:111-114`.

Sources: `src/lib/goals.ts:1-126`
