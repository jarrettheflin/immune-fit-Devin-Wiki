## Purpose and Scope
This page details the implementation of the wearable device connection lifecycle in immune.fit via the self-hosted Open Wearables (OW) pipeline. It covers the device catalog definitions and privacy policies (`src/lib/catalog/devices.ts`), the identity mapping layer (`src/lib/wearables/accounts.ts`), the OAuth initiation route (`src/app/api/wearables/[provider]/connect/route.ts`), the asynchronous OAuth callback handler (`src/app/api/wearables/[provider]/callback/route.ts`), the user management surface (`src/app/(app)/connections/page.tsx`), and the disconnection server actions (`src/lib/actions/wearables.ts`).

## 1. Device Catalog & Provider Policies
The system maintains a centralized catalog of supported health and fitness platforms in `src/lib/catalog/devices.ts`. Each entry defines connection types (`oauth`, `app`, `later`), user-facing descriptions, and strict AI data usage rules (`AI_RULES`).

```
+-----------------------------------+     +----------------------------------------+
| DEVICES Catalog                   |     | AI_RULES Mapping                       |
| src/lib/catalog/devices.ts        |     | src/lib/catalog/devices.ts             |
+-----------------------------------+     +----------------------------------------+
| - id: "whoop" | connect: "oauth"  | --> | whoop: allowed: true                   |
| - id: "oura"  | connect: "oauth"  | --> | oura:  allowed: true (No embeddings)   |
| - id: "garmin"| connect: "oauth"  | --> | garmin:allowed: false (Requires §15.7) |
| - id: "strava"| connect: "later"  | --> | strava:allowed: false (API Policy §5.3)|
+-----------------------------------+     +----------------------------------------+
```

* **`DEVICES` array**: Defines supported integrations like WHOOP, Oura, Garmin, Apple Health, and Strava `src/lib/catalog/devices.ts:12-51`.
* **`isDeviceId` & `deviceName`**: Type guards and lookup helpers for validating provider parameters `src/lib/catalog/devices.ts:55-61`.
* **`AI_RULES` & `aiAllowedSources()`**: Restricts which data sources can be exposed to AI companion context windows based on third-party developer agreements and privacy regulations `src/lib/catalog/devices.ts:68-91`.

Sources: `src/lib/catalog/devices.ts:1-92`

## 2. Wearable Accounts & Privacy Boundary
To prevent external exposure of internal user IDs to the Open Wearables instance, `src/lib/wearables/accounts.ts` establishes an isolated mapping layer between Supabase users and OW users.

```
+-------------------+        +---------------------+        +---------------------------+
| profiles          |        | wearable_accounts   |        | Open Wearables API        |
| src/lib/dal.ts    |        | src/lib/wearables/  |        | src/lib/wearables/client.ts|
+-------------------+        +---------------------+        +---------------------------+
| id (UUID)         |<------>| user_id             |        |                           |
| timezone          |        | ow_user_id (UUID)   |<------>| ow.createUser()           |
+-------------------+        +---------------------+        +---------------------------+
```

* **`getOwUserId(userId)`**: Queries the `wearable_accounts` table to retrieve the associated Open Wearables user UUID `src/lib/wearables/accounts.ts:14-22`.
* **`getOrCreateOwUserId(userId)`**: Creates an anonymous OW user via `ow.createUser()` if none exists, persisting the mapping via an upsert with race condition handling `src/lib/wearables/accounts.ts:25-39`.
* **`accountForUser` & `accountForOwUser`**: Hydrates account records with local profile timezone data (`profiles.timezone`) to ensure telemetry processing respects user local time `src/lib/wearables/accounts.ts:41-60`.

Sources: `src/lib/wearables/accounts.ts:1-74`

## 3. OAuth Connection Initiation (`/api/wearables/[provider]/connect`)
When a user clicks "Connect" on the connections dashboard, they invoke the GET route at `/api/wearables/[provider]/connect`. Because this route performs stateful mutations (creating OW users and fetching consent URLs), it must never be prefetched and is rendered as a plain HTML `<a>` tag rather than a Next.js `<Link>` component `src/app/api/wearables/[provider]/connect/route.ts:10-15`.

```
Title: "OAuth Connection Initiation Flow"
sequenceDiagram
    autonumber
    participant Browser as "Browser"
    participant Route as "GET /api/wearables/[provider]/connect"
    participant DAL as "requireUserId()"
    participant Accounts as "getOrCreateOwUserId()"
    participant OWClient as "ow.authorizationUrl()"

    Browser->>Route: GET /api/wearables/whoop/connect
    Route->>DAL: requireUserId()
    DAL-->>Route: userId
    Route->>Route: isDeviceId(provider) & connectableProviders()
    Route->>Accounts: getOrCreateOwUserId(userId)
    Accounts-->>Route: owUserId
    Route->>OWClient: ow.authorizationUrl(toOwProvider(provider), owUserId, callback)
    OWClient-->>Route: authorization_url
    Route-->>Browser: HTTP 307 Redirect (authorizationUrl)
```

* **Validation**: Validates that `provider` is a recognized `DeviceId` and is present in `connectableProviders()`. Invalid providers trigger a redirect to `/connections?error=unavailable` `src/app/api/wearables/[provider]/connect/route.ts:19-21`.
* **Redirect Execution**: Obtains an authorization URL from Open Wearables and issues an HTTP 307 redirect to the provider's external consent portal `src/app/api/wearables/[provider]/connect/route.ts:23-34`.

Sources: `src/app/api/wearables/[provider]/connect/route.ts:1-35`, `src/app/(app)/connections/page.tsx:104-107`

## 4. OAuth Callback Handler (`/api/wearables/[provider]/callback`)
Upon successful authorization at the provider, Open Wearables redirects the browser back to `/api/wearables/[provider]/callback`.

* **Stateless Verification**: Query parameters returned by the provider are ignored in favor of re-querying Open Wearables directly via `accountForUser(userId)` and `syncConnections(account)` `src/app/api/wearables/[provider]/callback/route.ts:9-24`.
* **Database State Check**: Verifies connection success by querying the `device_connections` table via an admin Supabase client `src/app/api/wearables/[provider]/callback/route.ts:25-32`.
* **Result Dispatch**: Redirects the client back to `/connections?connected=[provider]` or `/connections?error=[provider]` based on the verified status `src/app/api/wearables/[provider]/callback/route.ts:36`.

Sources: `src/app/api/wearables/[provider]/callback/route.ts:1-37`

## 5. Connections Dashboard & Disconnection Management
The user-facing management surface lives at `/connections` (`src/app/(app)/connections/page.tsx`). It renders connection statuses, last synchronization timestamps, and disconnection forms.

```
Title: "Connections Dashboard Component Hierarchy"
graph TD
    ConnectionsPage["ConnectionsPage\nsrc/app/(app)/connections/page.tsx"] --> ResultBanner["ResultBanner\nsearchParams parsing"]
    ConnectionsPage --> DeviceList["DeviceList\nsrc/app/(app)/connections/page.tsx"]
    
    DeviceList --> SupabaseQuery["Supabase\ndevice_connections query"]
    DeviceList --> DisconnectedState["Connect <a> / Pending Button"]
    DeviceList --> ConnectedState["DisconnectForm\nsrc/components/connections/disconnect-form.tsx"]

    DisconnectForm --> ServerAction["disconnectDevice()\nsrc/lib/actions/wearables.ts"]
    ServerAction --> OWRevoke["ow.disconnect() / ow.deleteProviderData()"]
    ServerAction --> DBDelete["DELETE device_connections\n(+ device_metrics / activity_logs)"]
```

* **`DeviceList` Component**: Interrogates the `device_connections` table for the authenticated user and matches them against the `DEVICES` catalog `src/app/(app)/connections/page.tsx:59-86`.
* **`DisconnectForm` Component**: Implements a two-step confirmation dialog allowing users to optionally purge all historical telemetry imported from the provider `src/components/connections/disconnect-form.tsx:10-40`.
* **`disconnectDevice` Server Action**: Revokes tokens via Open Wearables (`ow.disconnect` or `ow.deleteProviderData`), deletes the corresponding row from `device_connections`, and conditionally cascades deletions across `device_metrics` and `activity_logs` if `delete_data` is selected `src/lib/actions/wearables.ts:18-54`.

Sources: `src/app/(app)/connections/page.tsx:1-120`, `src/components/connections/disconnect-form.tsx:1-40`, `src/lib/actions/wearables.ts:1-54`
